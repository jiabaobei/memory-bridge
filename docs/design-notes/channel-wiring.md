# 设计说明：通道接线描述（配一次，各端自动）

版本：v0.27.0（2026-09-10） · 实现：`channel.py`（描述读写）+ `netdisk_sync.py`（凭据整理/口令链/状态）+ `wizard.py`（消费侧自动接线）

## 问题

用户在新设备上安装记忆桥时，会被问一次「配你的坚果云 / OneDrive」。而同一件事，
在第二台、第三台设备上又要从头配一遍——每个 AI 客户端、每个端各配一次。
这与「极度简洁易上手」直接冲突。

更细一层：**通道本身早就在自动传播了**——`channel.json`（通道身份）、
`channel.key`（通道密钥随通道走）、`devices/<设备>.json`（设备心跳），
新端只要装了同一个云盘客户端，`init` 就能自动认领通道、零提问。
真正没传播的只有一样：**接线描述**（接了哪家网盘、远端子路径、角色、凭据）。

## 决策

在通道目录里放一个**只写一次**的接线描述 `wiring.json`：

- 首次配置那台设备写它（`wizard` 引导接线时经 `on_connect` 回调拿到凭据，
  或 `membridge netdisk-connect` 时直接写）；
- 其他端 `init` 读到即**自动接上**（`wizard.adopt_wiring`），不再问账号与密码。

明文部分只有写者 / 时间 / 版本 / 通道 ID；**凭据整块加密**。

## 为什么必须「只写一次」

多端状态一律「每端只写自己文件」是项目的铁律，起因是网盘上的**共享可变文件**：
两端同时读-改-写，后落地的那次会覆盖前一次（丢更新），网盘还可能生成
`xxx (1).json` 冲突副本。

接线描述的正确形态因此是「**一台设备的文件**」，不是「大家的公共看板」：
写者唯一（`written_by` 不是本机就只读），所以它永远不会出现并发写。
想接手/重配时，删掉云盘里的 `wiring.json` 再重跑一次即可——不需要为罕见的
「换主配置机」场景先造一个 `--force` 开关（YAGNI）。

## 加密与信任边界（诚实说明）

凭据用的是**差分包同一条加密链**（`transport.PassphraseCryptor`：
Fernet + PBKDF2-HMAC-SHA256，随机盐随文件携带），口令回落链也收在一处
（`netdisk_sync.wiring_passphrase`）：显式口令 / `MEMBRIDGE_PASSPHRASE` → 通道密钥。

**关键取舍要说清**：如果用户没有另设 `--passphrase`，加密用的就是通道密钥，
而通道密钥本身也在这个目录里（`channel.key`，当初特意设计成「随通道走、各端零输入」）。
所以此时加密的强度等于**混淆 + 防明文落地 / 防误分享**，不是抵抗拿到整个通道目录的人。
这不是新增泄露面，而是与 `channel.key` **同一等级的既有面**。

真正的缓解手段是产品已有的选择：配的是**可一键作废的应用密码**（不是账户密码）。
需要严格端到端时另设 `--passphrase`，此时口令优先、密钥不在通道里，强度随之提高。

**拿不到钥匙就不写**（返回 `nocrypto`）——宁可少一个文件，也不落明文凭据。

## 为什么不放进 `channel.json`

`channel.json` 的模块注释里写着一句承诺：**纯元数据，不含口令、不触碰任何记忆内容**。
把凭据塞进去等于自己毁约（`tests/test_channel.py` 正有一条守卫在查这个）。
所以另开一个文件：通道清单保持干净，凭据单独加密存放。

## 被否掉的方案

- **重写/合并各端的向量或记忆来对齐**：违反「绝不动记忆本身」。接线描述是
  基础设施元数据，不进 `nodes` / `edges`，与内容冻结原则无关。
- **新增一个共享清单文件让各端维护**：正是上面说的丢更新来源。
- **`gateway --invite-ai` + 公网隧道**：撞 v0.11「绝不开公网明文端口」的承诺。
- **把凭据写进本机保险库就完事**：保险库是机器绑定（DPAPI / 本机用户），
  恰好**不能**跨端——那是 `show-passphrase` 手工配对那套要解决的问题，
  与「配一次各端自动」相反。

## 老位置的迁移

接线状态原先存在**通道目录**里的 `.membridge-netdisk.json`，现已改回本机文件
`<库目录>/netdisk.json`。读不到本机文件时回落读老位置并**就地迁移**：
老用户零动作升级。通道里的老文件**不删**——别的设备可能还在读它，
删除是不可逆的破坏。

（原先那个位置本身就是铁律要防的形态：读-改-写 + 条目里存着本机路径
`local_dir`，每端都不同的值。改成每端本机文件后，`cli._netdisk_round`
「对本机未接线的 provider 也硬跑 rclone」那个不一致自然消失。）

## 边界与未尽事项

- 描述里带**非密字段**（provider / 远端子路径 / 角色）时即使没凭据也照写：
  别端至少知道「该接哪家、远端子路径是什么」，凭据可以让用户补一次。
- OneDrive 的 OAuth token 换机器后可能仍有效（个人版一般可长期用），
  但若失效，`adopt_wiring` 只会打印一条「未接上」的提示，**绝不阻断安装**。
- 目前**不做**「描述变更的同步收敛」：写者唯一意味着描述不会漂移，
  也就不需要版本向量或冲突解决。
